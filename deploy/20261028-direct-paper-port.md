# 2026-10-28 게임 서버 포트 정정

`server.properties`의 `server-port`를 25566에서 **25565**로 변경했다. `server-ip=10.0.0.217`은 유지했다. 현재 게임 연결은 Paper가 직접 수신하며 Minecraft용 프록시나 포트 리다이렉션을 사용하지 않는다.

- 25565 리스너 소유자: Java/Paper. 외부 `mud.danta.qzz.io:25565` 상태 조회에서 Paper 26.3 응답을 확인했다.
- 25566: 리스너가 없고 기존 UFW 허용 규칙을 삭제했다. 외부 접속도 되지 않는다.
- HAProxy: 중지하고 자동 시작을 해제했다. 게임·포탈 연결에서 사용하지 않는다.
- 접속 제한: `connection-throttle: 4000`은 유지했다. 프록시 때문에 접속자 IP가 하나로 합쳐지는 원인을 제거했다.
- 포탈채팅: ServerChatMirror의 `mirror-url`을 `https://127.0.0.1:24443`으로 변경했다. 기존 인증서의 localhost/127.0.0.1 SAN을 확인했고 인증서·호스트명 검증을 유지했다. 실제 수신 메시지와 Java의 loopback 연결을 확인했다. 별도 공개 포트는 열지 않았다.

## 재기동과 복구 기록

사용자가 이번 포트 수정에 한해 재기동을 승인했다. 이 작업은 02:10 KST에 Minecraft를 정상 종료·시작했다. 그때 오디오 서비스 재기동이나 플러그인 JAR 교체는 수행하지 않았다.

포탈 플러그인의 `/chatmirror reload`는 표시 설정만 갱신하며 연결 URL은 갱신하지 않는다는 점을 뒤늦게 확인했다. 사용자의 명령 실행만으로 URL이 반영됐다고 판단하지 않았다. 잠시 기존 캐시 주소의 포탈 트래픽만 loopback으로 연결하는 임시 경로를 사용했으며, 최종적으로 해당 경로와 임시 systemd unit을 모두 제거했다. Minecraft 트래픽에는 이 경로를 사용하지 않았다.

검증 도중 별도 재기동 기록이 관찰됐다: 오디오 서비스 02:17:29 KST, Minecraft 02:17:41 KST. 이 포트 작업 명령은 해당 추가 재기동을 실행하지 않았으며, 이 기록만으로 수행 주체는 확인되지 않았다. 새 Minecraft 프로세스가 저장된 loopback 포탈 주소를 읽었고 포탈 수신이 복구됐음을 확인했다.

최종 상태는 `server-port=25565`, HAProxy 비활성, 25566 비수신·방화벽 차단, 포탈 loopback 직결이다. 임시 NAT 규칙은 남아 있지 않다. 원복 자료와 실행 영수증은 서버의 `/home/ubuntu/mc-luck-defense-deploy/direct-paper-port-review-1793114753/`에 보관한다.
