# 2026-10-27 재생 장애 확인

운영 nginx 로그에서 `/api/v1/playback` HTTP 400이 반복됐다. 조사 구간의 실패 2,976건 중 마지막 요청 음원과 연결할 수 있었던 2,929건은 모두 310초보다 긴 음원이었다. 예: Pretender 335.593초, 수평선 312.118초, 난데모나이야 344.060초. HTTP 본문은 운영 로그에 저장하지 않으므로 개별 실패 본문의 값은 직접 확인하지 않았다.

전체 길이 음원을 도입하면서 재생 보고의 `bufferedUntilMs`에 남아 있던 310,000ms 고정 제한을 갱신하지 않은 결함을 재현했다. 이 제한에 걸리면 준비·시작 보고가 거절되고, 확인되지 않은 라운드를 건너뛸 때 플러그인이 해당 곡을 라운드 수에서 빼는 별도 결함도 재현했다.

브라우저에서는 중단된 출력 확인의 Promise 완료 처리가 곧바로 다음 출력 확인을 호출할 수 있었다. 일반 재생 실패도 반복 호출될 수 있어 자동 재시도 사이에 2초를 두었다. 같은 참가자 목록의 반복 DOM 생성도 제거했다. 백엔드는 개별 재생 보고마다 전체 참가자에게 상태를 방송하던 처리를 최초 접속 등 상태 변경에만 수행하도록 수정했다.

장애 순간 CPU 표본은 확보하지 못했다. 조사 중 3초 표본은 Java 약18%, Rust 약0.3%였으며 CPU 급증의 크기와 서버/브라우저별 기여도는 확인되지 않았다. 메모리 부족·OOM·서버 과부하 경고는 조사한 로그에 없었다. 디스크는 약97% 사용 중으로 별도 용량 정리가 필요하다.

22:33:01 KST `/noqui stop` 직후 네 건의 플레이어 복구 경고가 있었다. 이전 코드는 예외 원인을 기록하지 않아 근본 원인은 미확인이다. 수정본은 플레이어 UUID와 예외 내용을 남긴다.

## 적용 상태

- 브라우저 수정은 nginx의 `/app.js` 정적 경로로 반영했다. 기존 탭은 새로고침이 필요하다. SHA-256: `32baa3848a79b30681642e503723bd638c3d761d9d431488046e78e685ebe8bb`.
- Minecraft PID `1509319`, 오디오 서비스 PID `1509316`은 변경되지 않았다. nginx 설정 검사 후 연결을 끊지 않는 reload만 수행했다.
- 백엔드와 플러그인 수정본은 저장소에 반영했으며 실행 중 코드에는 적용하지 않았다. 서버·오디오 서비스 재시작 및 플러그인 reload 금지 조건을 지켰다.
- 신규 플레이리스트와 변경된 녹음은 현재 서비스의 불변 메모리 목록을 갱신할 경로가 없어 파일 준비와 실제 활성화를 구분해야 한다.
