# Noqui 1.0.8

Paper 26.3 / Java 25용 노래퀴즈 플러그인입니다. 오디오는 Rust 서비스가 처음 115초(짧은 곡은 전체)를 약 48kbps Ogg Opus로 캐시하고 브라우저가 재생합니다. 게임·출제권·정답·점수는 Paper가 결정합니다.

## 빌드

저장소 루트에서 순서대로 실행합니다.

```powershell
python noqui/lobby-assets/build_pack.py --check
python noqui/lobby-assets/test_pack.py
mvn -B -ntp -f noqui/plugin/pom.xml clean install
mvn -B -ntp verify
cargo test --locked --manifest-path noqui/web/Cargo.toml
```

산출물은 `noqui/plugin/target/noqui-plugin-1.0.8.jar`, `target/mc-luck-defense-1.0.30.jar`입니다. Moma는 Noqui API에 provided 의존성을 사용하며 API는 Noqui JAR에만 포함됩니다. Noqui 없이 Moma만 기동하는 경로도 유지합니다. 최초 통합은 두 플러그인을 설치한 뒤 정상 재시작합니다. Noqui 1.0.8은 실제 재생 확인과 대기곡 캐시 보호 계약을 지원하는 웹과 함께 적용합니다. 웹을 먼저 적용한 뒤 Noqui JAR를 교체하고 정상 재시작하며 이번 변경은 Moma 1.0.30과 Noqui 1.0.8 두 JAR를 함께 교체합니다. Moma 런타임 재로드는 매번 현재 서비스 제공자를 조회합니다.

Noqui의 변환 오디오 캐시는 최대 5 GiB LRU로 관리하며 Moma BGM 캐시와 저장·회수 대상을 공유하지 않습니다. 캐시를 재사용하면 최근 사용 순서가 갱신되지만 pin heartbeat 자체는 재사용으로 세지 않습니다. 대기곡·현재 곡·진행 중 스트림은 회수에서 제외하고, 보호하지 않는 파일로 공간을 확보할 수 없으면 새 저장을 거절합니다.

Java는 내부 `/internal/v1/sync`의 최상위 `retainedMediaIds`에 현재 세션의 전체 보관 목록을 보냅니다. 최대 64개 UUID를 중복 제거하며 동일 미디어의 마지막 제출 참조가 없어질 때 해제합니다. READY 응답만으로 준비를 완료하지 않고, 해당 ID를 포함한 실제 sync 패킷의 성공 ACK를 받은 뒤 QuizGame에 전달합니다. ACK 실패는 준비 실패·출제권 반환으로 처리하며 취소된 요청의 늦은 ACK는 무시합니다. 취소·이탈·종료·재시작은 다음 전체 목록에 반영하고 정상 종료는 빈 배열을 보낸 뒤 연결을 닫습니다. READY/cache hit의 60초 임시 보호는 첫 sync 전의 틈만 막으며 장기 대기열 보호를 대신하지 않습니다. Rust는 승인된 pin 목록을 영구 보관하고 재시작 후에도 보호합니다. 필드가 없는 구버전 요청은 빈 배열로 해석하거나 eviction을 활성화하지 않습니다. 이 목록은 공개 state/SSE와 대기곡 메타데이터에 노출하지 않습니다.

팩의 소스와 생성·검증 방법은 [로비 에셋 안내](lobby-assets/README.md)를 따릅니다. 검증한 `noqui/lobby-assets/lobby-pack.properties` 하나만 JAR 루트에 포함하며 ZIP은 포함하지 않습니다. 팩 ZIP을 해당 내용 해시의 공개 URL에 먼저 게시한 후 플러그인을 기동합니다. 기존 `plugins/Noqui/lobby-pack.properties`가 있으면 자동 덮어쓰지 않으므로 팩을 바꿀 때 검증한 새 descriptor를 함께 반영합니다. CI는 Python 표준 라이브러리로 팩 재현성과 descriptor를 먼저 확인한 뒤 Maven을 실행합니다.

## 설정과 이용

정제된 `noqui_cabin` 월드를 서버 정지 중 반입합니다. 기본 스폰은 `(411.5, 11, -205.5)`, 경계 중심은 `(416, -192)`, 크기는 250입니다. 바깥 청크는 void generator를 사용하며 스폰 안전성과 월드 보호를 적용합니다.

`plugins/Noqui/config.yml`의 bridge 주소는 루프백 `http://127.0.0.1:8788`, 공개 주소는 `https://noqui.danta.qzz.io`입니다. `bridge.secret-file`에는 Rust와 같은 32바이트 키 파일 또는 64자리 16진수 키 파일을 지정합니다. 실제 키와 `credits.json`, Rust의 `media.sqlite` 안에 있는 `song_catalogue`는 비공개 서버 데이터입니다. 웹 설정은 `deploy/`를 따르며 Minecraft 주소는 `mud.danta.qzz.io`입니다.

OP 명령은 `/noqui start [rounds]`, `limit <rounds>`, `stop`, `skip force`, `hint`, `pause`, `resume`, `give <nickname|@a> [amount]`, `status`, `admin`입니다. 일반 참가자는 `/noqui`로 메뉴를 열고 `/noqui skip`으로 투표하며 `/noqui bgm`으로 BGM을 켜거나 끄고 `/noqui leave`로 퀴즈에서 나갑니다. `/noqui start`는 무제한, `/noqui start 200`은 최대 200라운드입니다. `/noqui limit 0`으로 무제한 전환하며 양의 정수로 실행 중 제한을 바꿉니다. 이미 시작한 라운드보다 낮은 양수 제한은 거절하고, 남은 제한을 초과한 대기 곡은 취소·반환합니다. 콘솔은 접속자가 없어도 시작할 수 있습니다.

퀴즈 시작 시 활성 디펜스·관전 세션이 없는 접속자는 cabin으로 안내합니다. 디펜스·관전은 현재 위치에서 동시에 참여합니다. Moma에서는 퀴즈가 진행 중일 때만 보호된 `노래퀴즈` 아이콘 하나가 표시됩니다. 로비는 3번 칸, 게임·관전은 4번 칸이며, 수량은 출제권 보유량에 맞춰 최대 64개로 표시하고 설명에 정확한 장수를 적습니다. 0장도 아이콘은 남습니다. 우클릭 메뉴는 `로비`와 `출제`뿐입니다. 로비 이동은 기존 세션 나가기 잠금·정리 절차를 따르며, 출제는 진행 중인 게임을 유지합니다. 두 로비의 `미니게임` 나침반은 이동할 로비를 고르는 메뉴를 엽니다. 기존 F키, `/mud`, 포털의 게임 참가 경로는 유지합니다. cabin에는 Moma와 같은 이름과 색의 `환경설정` 비교기와 `특성 선택` 마법이 부여된 책도 제공합니다. Noqui 전용 키를 사용하며 기존 이동 위치, 보조 손, 커서를 존중하고 빈 슬롯에만 부족한 도구를 넣습니다. 공간이 없으면 기존 아이템을 덮어쓰지 않습니다. 이동 도구만 버리기와 외부 보관, 제작 투입을 막으며 출제권과 가젯의 이동 및 버리기는 유지합니다. cabin의 F키는 기본 보조 손 교환이며 Moma의 기존 F 메뉴는 유지합니다.

브라우저 연결 창은 퀴즈 참가자에 대해 웹 서비스가 최근 연결 끊김을 확인한 경우에 자동으로 열립니다. 오디오 준비 상태와 브라우저 접속 상태는 별개이며, 서비스 장애나 오래된 응답은 연결 끊김으로 취급하지 않습니다. 출제 입력 창·상점 등 다른 화면을 덮지 않고, 연결되면 자신의 연결 창만 닫습니다. 다시 표시하기 전에는 유예 시간을 둡니다. 명시적으로 퀴즈에서 나간 사람은 자동으로 재참가시키지 않습니다. F키와 제어 종이의 브라우저 기능은 제거했습니다. 수동 복구는 `/noqui connect`, 제출 취소·넘기기 투표는 `/noqui`를 사용합니다. cabin 출제권은 손에 들고 우클릭하며, 인벤토리 안에서는 일반적인 이동·분할·보조 손 교환이 가능합니다.

실물 출제권은 cabin 안에서만 보유 잔액에 맞춰 표시합니다. Moma 로비·게임에는 실물 출제권 대신 위의 보호된 대리 아이콘만 표시하며, 퀴즈가 꺼지면 아이콘도 사라집니다. `/noqui give <nickname|@a> [amount]`는 기본 1장, 한 번에 1..1000장을 영구 장부에 지급합니다. `@a`는 현재 접속자 전체이며 알려진 닉네임은 오프라인 지급도 지원합니다. `/money`는 누구나 자신의 별빛과 정답 포인트를 확인하며, OP 또는 콘솔은 `/money give <nickname|@a> [amount]`로 별빛을 지급합니다. 생략한 수량은 1이며 별빛 아이콘은 ✦입니다. 수량과 모든 대상의 보유 한도를 먼저 검사하고, 호출과 수신자별 고유 거래 ID를 사용합니다. 저장 실패로 일부만 처리되면 성공 수와 실패한 이름을 알려주므로 실패한 대상만 다시 지급할 수 있습니다. 오프라인이거나 인벤토리가 가득 찬 경우 지급을 보류하고 공간이 생기면 다시 전달합니다. 출제권을 떨어뜨리면 소유 잔액을 즉시 차감하고 고유한 지상 수령권으로 전환합니다. 다른 플레이어가 주우면 한 번만 이전하며 공간이 일부만 있으면 나누어 줍습니다. 오래된 아이템 복사본, 재접속과 인벤토리 복원으로 잔액이 늘어나지 않습니다. 떨어진 아이템의 자연 소멸·파괴는 원래 잔액으로 환급하지 않습니다. 장부 v2는 기존 v1 잔액·예약·구매 영수증을 보존합니다. 지상 위치·나이는 30초마다 한 번에 저장하고 소유권 변경은 즉시 저장합니다.

라운드 표시는 `현재 라운드/이번 퀴즈 등록곡 수`로 통일합니다. 빈 퀴즈는 `0/0`이며, 이미 재생한 곡과 유효한 현재 곡, 대기곡을 합산합니다. 재생한 곡은 끝나도 분모에 남고, 재생 전 취소, 실패, 반환된 제출은 제외합니다. 새 퀴즈와 서버 재시작은 등록 수를 초기화합니다. `/noqui start 200`과 `/noqui limit`은 별도의 진행 상한이며 표시 분모나 영구 곡 목록 크기가 아닙니다. 지급 메시지, 상태, 메뉴, 상점과 아이템 설명의 장식용 중간점은 사용하지 않습니다.

라운드는 기본 무제한이며 명령으로 0(무제한) 또는 최대 2,147,483,647까지 제한합니다. 유효한 제출을 수락할 때 출제권 한 장을 예약하며, 입력 창 취소·유효하지 않은 입력에는 소모하지 않습니다. 재생 전 취소·이탈·준비 실패·종료는 한 번만 실물로 반환하고 실제 재생 시작 때 사용을 확정합니다. 입력 중 다른 라운드나 지급이 진행되어도 같은 퀴즈·회원권에서 현재 자격을 다시 확인하며, 이전 퀴즈 입력 창은 사용할 수 없습니다. 한 사람당 재생 전 한 곡, 전체 최대 64곡을 수락 즉시 미리 변환합니다. 장기 변환 대기열은 64×300초와 15분 여유의 유한 예산으로 보호하며 기존 15분 만료로 정상 대기 곡을 버리지 않습니다. 변환된 곡은 브라우저가 없더라도 조용히 보존하고, 현재 라운드에서 유효한 브라우저 한 명이 PREPARED를 보고하면 즉시 전달 여유 1초와 3, 2, 1 카운트다운을 시작합니다. 연결되지 않은 다른 참가자 때문에 20초를 기다리지 않으며, 준비된 브라우저가 없으면 계속 대기합니다. 카운트다운 예정 시각 이후 브라우저는 재생을 시도하되, 실제 재생 진행을 확인하기 전에는 정답 접수·종료 타이머·라운드 수 증가·출제권 사용 확정을 보류합니다. 브라우저 한 명의 유효한 진행 확인이면 시작할 수 있으며, 재개도 새 재생 세대의 확인을 다시 기다립니다. 대기 중 남은 곡 길이·힌트·무경쟁 추가 정답 창은 동결합니다. 준비 실패는 라운드를 소비하지 않으며 정지·스킵·시간 만료 뒤에는 원본과 같이 1초 후 다음 라운드로 전환하거나 종료합니다. `round-seconds`는 1..115이고 실제 오디오 길이를 넘지 않습니다.

제출한 제목, 태그와 YouTube URL은 Rust 전용 `media.sqlite`의 비공개 `song_catalogue`에 저장합니다. 준비 요청의 안정적인 `requestId`와 `videoId`, 선택 필드 `song: {title,tags}`를 사용하며, 백엔드는 변환 시작 전에 메타데이터를 기록합니다. Java는 더 이상 라운드 상태가 바뀔 때마다 `songs.yml`을 쓰지 않습니다. 기존 파일은 시작 시 비동기로 `/internal/v1/catalogue/import`에 옮기며, UUID와 원래 URL, 제목, 태그를 유지합니다. 배치는 최대 50개이며 실제 UTF-8 요청은 64 KiB 미만입니다. 모든 유효 행의 `savedCount` 승인이 끝나야 원본과 동일한 백업 및 파일 해시 완료 표시를 저장합니다. 원본 YAML은 삭제하거나 덮어쓰지 않습니다. 실패하면 원본을 그대로 두고 다음 시작에서 같은 ID로 재시도하며, 잘못된 행도 원본과 백업에 남깁니다. 이 영구 목록은 이번 퀴즈의 등록곡 분모에 포함하지 않습니다.

Java는 현재 회원권·라운드·재생 세대가 일치하고, 예정 시작 이후의 `PLAYING` 보고가 5초 이내이며 미래 시각이 아닐 때만 시작을 확정합니다. 보고 위치는 저장된 앵커보다 크고 클립 끝 이하여야 합니다. 클라이언트는 `play()` 완료와 seek가 아닌 자연스러운 시간 진행을 확인한 뒤 이 상태를 보고해야 합니다. Backend ACK나 `PREPARED`만으로는 라운드를 시작하지 않습니다. 위치 보정은 저장된 앵커에서 최대 2초×재생속도, 보고 나이 보정도 최대 2초×재생속도로 제한하고 클립 끝을 넘지 않습니다. 세대는 그대로 유지하므로 시작 확정 때 재생을 다시 초기화하지 않습니다. COUNTDOWN 대기 중 프런트는 예정 시각 경과를 seek 목표에 누적하지 않고 저장된 위치에서 재생을 시도하며, 실제 재생이 진행되면 고정 앵커로 되감지 않아야 합니다. 기존 `status`·`positionMs`·`lastSeenAtMs` 계약을 사용합니다. 웹페이지에서 **연결하기**를 누르면 무음 오디오 확인 후 파형 모션과 함께 재생 화면으로 전환합니다. 페이지 이동이나 오디오 요소 교체 없이 연결하므로 다음 곡에도 초기 상호작용이 유지됩니다.

제목·태그는 대소문자/공백/기호를 무시한 부분 문자열로 판정합니다. 원본처럼 출제자를 포함한 모든 참가자가 자기 곡에도 정답을 제출할 수 있으며 별도의 솔로 예외는 없습니다. KAKC가 변환한 현재 채팅을 HIGH 우선순위에서 검사하고, legacy/modern 중복 콜백도 같은 라운드·UUID에 한 번만 보상합니다. 일반 모드에서는 첫 정답을 즉시 공개하되 곡은 끝까지 재생합니다. 경쟁 점수는 정답당 1점이고 영구 정답 포인트는 기본 1, 제목점수보너스 활성화 시 제목 정답에 2입니다. 현재 라운드에서 정답을 인정받은 참가자는 채팅에 `스킵`을 입력해 즉시 넘길 수 있습니다. 앞뒤 공백만 제거한 정확한 `스킵`만 처리하며, KAKC가 한글로 변환한 메시지도 적용합니다. 무경쟁에서는 모든 정답자가 사용할 수 있고, 이미 투표했거나 일시정지·재개 카운트다운 중이어도 사용할 수 있습니다. 현재 정답자가 아닌 사람의 `스킵`은 평소처럼 채팅·정답 판정으로 처리합니다. 지연·중복 채팅 콜백은 같은 퀴즈·라운드·회원권과 현재 정답자 자격을 다시 확인하므로 다음 라운드나 재입장 후에는 실행되지 않습니다. `/noqui skip`과 기존 `넘기기 투표` 버튼은 정답자도 포함해 엄격한 과반수 투표를 유지하며 OP의 `skip force`는 별도입니다. 시간 만료·강제/투표/자동 스킵 시 정지 효과음은 한 번 재생하고, 이미 공개한 정답과 승리 효과음은 반복하지 않습니다.

원본의 일곱 모드 `날먹금지`, `스피드x2`, `맞추면바로스킵`, `무경쟁`, `제목점수보너스`, `오직제목만`, `오토힌트`를 `/noqui mod list`, `/noqui mod add <이름>`, `/noqui mod remove <이름>`으로 관리합니다. `/noqui ban list|add|remove`는 날먹금지 키워드를 관리합니다. 모든 변경은 다음 라운드부터 적용되어 진행 중 정답 공개·점수·속도 규칙을 바꾸지 않습니다. 기존 `match-skip`, `title-bonus`, `auto-hint` 설정은 명시적인 `modes` 목록이 없을 때 유지하며, 첫 모드 저장 시 목록으로 전환합니다. 새 설정은 제목점수보너스만 기본 활성화합니다.

맞추면바로스킵 OFF는 일반/무경쟁 모두 곡을 계속 재생합니다. ON이면 일반 모드는 첫 정답에서 즉시 멈추고, 무경쟁은 첫 정답 뒤 2초 동안 다른 참가자의 정답을 추가로 받은 후 멈춥니다. 무경쟁은 참가자별 한 번 득점하며 정답자끼리의 후속 채팅만 비공개로 전달하고 마지막에 정답과 전체 정답자를 공개합니다. 스피드x2는 같은 115초 캐시를 피치 보정 없이 2배속으로 재생하므로 최대 재생 시간은 57.5초입니다. 일시정지·재개는 원본 오디오 위치와 2초 추가 정답 창의 남은 시간을 보존합니다. 오토힌트는 재생 중 9초 간격이며 최초 초성/밑줄과 이후 무작위 공개 동작을 유지합니다.

cabin의 전체 인벤토리는 바깥 Moma 인벤토리와 별도로 영구 보관합니다. 일반 아이템·가젯·방어구·보조 손·커서와 칸 배치는 퇴장·종료·접속 종료·디펜스 전환 전에 저장하고 다음 입장 때 복원합니다. 출제권은 저장된 복사본을 영구 장부와 대조하며 가젯은 고유 일련번호를 검증하므로 이미 사용하거나 떨어뜨린 아이템이 다시 지급되지 않습니다. 퀴즈 입장 때 원본 BGM 설정을 저장하고 OFF로 시작하며 `/noqui bgm`으로 변경합니다. BGM은 실제 Moma 참가·관전 세션의 재생 목록에서만 재생하고 cabin에서 기본곡을 자동으로 틀지 않습니다. 퀴즈 이탈은 원본 설정을 복원합니다. Noqui 보스바는 사용하지 않으며 기존 제목·채팅·카운트다운·TAB 표시를 유지합니다. 출제권 또는 대리 아이콘으로 새 입력 창을 열 때 YouTube·제목·태그는 항상 비어 있습니다.

`quiz-active`가 true였던 정상 재시작은 `quiz-limit`에 저장된 제한으로 새 제출 대기 상태를 만듭니다. 이전 곡·타이머·작업·브라우저 회원권은 재사용하지 않습니다. 점수는 한 실행에 한정되며 출제권 잔액과 개인 제출 기록은 보존합니다.

치장 목록은 canonical `noqui/lobby-assets/lobby-cosmetics.json`을 JAR 루트 `/lobby-cosmetics.json`으로 포함해 읽습니다. 스키마는 `schemaVersion: 1`, `cosmetics: [{id,label,slot}]`이며 기존 여섯 ID와 슬롯을 보존합니다. ID는 영문 소문자로 시작하는 64자 이내 영문 소문자, 숫자, 밑줄이며 슬롯은 head, face, back입니다. 중복, 예약 ID 충돌, 빈 이름, 잘못된 슬롯과 기존 ID 누락은 거절합니다. 상점과 보유 목록은 한 페이지 21개로 나누고 이전, 다음, 상세 화면의 돌아가기는 원래 페이지를 유지합니다. 표시용 빈 상품은 넣지 않습니다. 메타데이터와 팩 descriptor만 JAR에 포함하며 팩 ZIP은 포함하지 않습니다.

GSit가 활성화된 경우 빈 주손으로 위쪽을 누른 안전한 계단, 반블록, 카펫, 이끼 카펫, 눈, 선반 버섯과 빈 주손 플레이어 상호작용을 GSit에 넘깁니다. 기존 취소를 되돌리거나 권한을 넓게 부여하지 않습니다. 컨테이너, 블록 편집, NPC, 보조 손 및 생물 생성 보호는 유지합니다.

## 별빛과 상점

`/money`는 내 별빛 ✦와 정답 포인트를 보여 줍니다. 실제 디펜스 참가자가 100라운드 단위 체크포인트 k에 도달할 때마다 즉시 10×k 별빛을 받습니다. 누적 지급량은 10×k×(k+1)/2이므로 99R=0, 100R=10, 200R=30, 300R=60, 1000R=550입니다. 건너뛴 체크포인트도 모두 따라 지급하고, 세션 UUID·플레이어 UUID·체크포인트 거래 ID로 종료·퇴장·접속 종료·리로드의 중복 지급을 막습니다. 관전자는 받지 않습니다. `rewards.yml`의 새 공식은 `milestones-v1`이며 이전 `starlight-per-round`는 무시합니다. 기존 지갑 잔액과 이미 저장된 이전 지급 의무는 원래 거래 ID로 보존합니다. 미저장 보상은 리로드를 막고 저장·전달 대기열에서 재시도합니다.

cabin의 상점 NPC 상자 GUI에서 구매합니다. 치장과 가젯은 별빛 또는 정답 포인트로 살 수 있으며 기본 가격은 1포인트=10✦ 비율입니다. 출제권은 100✦ 전용, 모든 치장과 삼단 점프는 200✦ 또는 20포인트, 사단 점프와 반중력은 400✦ 또는 40포인트, 망치와 눈폭탄은 100✦ 또는 10포인트입니다. 출제권 외의 기존 상품 기본 가격을 양쪽 통화 모두 10배로 조정했으며 잔액과 소유권은 그대로입니다. 가격을 시작할 때마다 곱하지 않습니다. `lobby.prices.<id>.starlight`와 `.points`의 명시적 사용자 값은 계속 우선합니다. 부모 세션이 확인한 라이브 설정은 `lobby.prices: {}`이므로 별도 설정 수정은 필요하지 않습니다. 치장은 두 게임에서 표시하며 가젯과 이단 점프는 cabin에서만 적용합니다. 구매 내역과 출제권 지급은 각 저장소의 동일 거래 ID로 재시도해 재시작 후 중복 지급을 막습니다. 리소스팩 URL·해시·가격과 로비 기능은 `lobby` 설정 및 별도 팩 자료를 따릅니다.

## 검증

Maven 검사는 크레딧 예약/확정/반환/재시작, 유한 라운드, 투표, 일시정지와 힌트, 비동기 취소, HUD 복구, 동시 참여, BGM 복구, HMAC 실제 HTTP 요청, 공개 전 정답 비노출을 포함합니다.

승인된 Paper 파일·EULA·정제 월드가 있을 때 격리된 fixture를 실행합니다.

```powershell
mvn -B -ntp -f noqui/plugin/pom.xml dependency:build-classpath -Dmdep.outputFile=target/smoke-classpath.txt
python noqui/plugin/smoke/run_paper_smoke.py
```

fixture는 `.runtime/noqui-plugin-smoke-*` 안에서 Paper를 두 번 부팅해 월드·스폰·경계, 네이티브 연결 창, 서비스 등록, 빈 서버 시작/종료, Moma 런타임 교체와 활성 상태 재시작을 확인합니다. 실제 클라이언트 화면과 브라우저 청취는 별도 검증 대상입니다.
