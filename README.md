# Noqui

Paper 26.3 / Java 25용 독립 노래퀴즈 플러그인입니다. 오디오는 Rust 서비스가 곡마다 처음 115초(짧은 곡은 전체)를 한 번 수집하여 약 48kbps Ogg Opus로 캐시하고, 브라우저가 직접 재생합니다. 게임 진행·출제권·정답·점수는 Paper가 결정합니다.

## 빌드

저장소 루트에서 순서대로 실행합니다.

```powershell
mvn -B -ntp -f noqui/plugin/pom.xml clean install
mvn -B -ntp verify
cargo test --locked --manifest-path noqui/web/Cargo.toml
```

산출물은 `noqui/plugin/target/noqui-plugin-1.0.0.jar`, `target/mc-luck-defense-1.0.25.jar`입니다. Moma는 Noqui 공개 API에 provided 의존성을 사용합니다. API는 Noqui JAR에만 포함되며, Noqui가 없는 기존 Moma 기동 경로도 유지됩니다. 최초 통합은 의존성 선언이 바뀌므로 정상 서버 재시작이 필요합니다. 이후 Moma 런타임 재로드 시 서비스 제공자를 교체하고 매 호출마다 현재 서비스를 조회합니다.

## 설정과 이용

정제된 `noqui_cabin` 월드를 서버 정지 중 반입한 뒤 Noqui를 활성화합니다. 원본 서버 플러그인이나 전체 월드는 복사하지 않습니다. 기본 스폰은 `(411.5, 11, -205.5)`, 경계 중심은 `(416, -192)`, 크기는 250입니다. 바깥 청크는 void generator를 사용합니다. 스폰의 바닥·머리 공간을 검증하며 월드 전체를 보호합니다.

`plugins/Noqui/config.yml`의 bridge 주소는 루프백 `http://127.0.0.1:8788`, 공개 주소는 `https://noqui.danta.qzz.io`입니다. `bridge.secret-file`에 Rust와 같은 32바이트 키 파일 또는 64자리 16진수 키 파일을 지정합니다. 실제 키와 `songs.yml`은 공개하지 않습니다. 웹 서비스 설정은 `deploy/`의 검토 자료를 따릅니다. Minecraft 접속 주소는 기존 `mud.danta.qzz.io`를 사용합니다.

OP 관리 명령은 `/noqui start [player]`, `stop`, `skip`, `hint`, `give [player]`, `status`입니다. `/noqui`는 네이티브 관리 창을 엽니다. 콘솔에서 접속자가 없어도 시작할 수 있으며, 첫 참가자가 출제권을 받습니다. 진행 중인 디펜스 참가자·관전자는 이동시키지 않습니다.

입장하면 네이티브 브라우저 연결 창이 먼저 열립니다. 비동기로 발급된 60초 링크의 `연결` 버튼을 누르며, 만료되면 `새 링크`로 갱신합니다. F키 또는 종이 아이템으로 메뉴를 열고 출제권이 있을 때 곡을 제출합니다. 제출 창은 연결 창을 자동으로 덮지 않습니다. 나침반은 퀴즈에서 나간 뒤 기존 디펜스 참가·관전 메뉴를 엽니다. 디펜스가 종료되면 활성 퀴즈로 돌아옵니다.

오디오 준비 및 브라우저 준비가 끝나야 시작합니다. 브라우저 준비는 최대 20초 대기하며, 준비된 브라우저가 없으면 같은 출제자에게 재제출을 안내합니다. 비동기 전달 여유 1초 후 3초 카운트다운을 예약하고, 웹 서비스가 해당 예약을 수락해야 정답 접수가 시작됩니다. 취소되거나 오래된 요청은 새 라운드에 영향을 주지 않습니다.

기본 라운드는 115초이며 실제 오디오 길이를 넘지 않습니다. 제목·태그는 대소문자/공백/기호를 무시한 부분 문자열로 판정합니다. 출제자는 자기 곡에서 득점할 수 없습니다. 최초 정답자에게 1점과 다음 출제권이 주어지며, 기본 설정에서는 시간이 끝날 때까지 곡이 계속됩니다. `match-skip: true`이면 정답 직후 넘깁니다. 참가자 스킵 투표는 없습니다.

퀴즈 입장 시 원래 BGM 키의 존재 여부·BYTE 값과 인벤토리를 복구 마커에 먼저 저장합니다. 참가 중 BGM을 켜면 기존 Moma 기본곡 리소스팩을 적용하고 재생합니다. 디펜스 세션은 만들지 않으며 OFF나 퀴즈 이탈 때 해당 곡만 정지합니다. 디펜스로 이동·종료·접속 종료·플러그인 비활성화 때 원본을 복원합니다. 비정상 종료로 남은 마커는 다음 접속에서 복원합니다. 기존 리소스팩을 전체 제거하거나 전체 소리를 정지하지 않습니다.

시작 여부는 `quiz-active`로 저장합니다. 정상 재시작 후 활성 상태였다면 새 대기 상태를 만들며, 이전 곡·타이머·준비 작업·브라우저 회원권은 재사용하지 않습니다. 점수는 해당 실행의 게임에 한정됩니다. 개인 제출 기록과 mediaId는 서버의 비공개 `songs.yml`에 저장됩니다.

## 검증

Maven 검사는 상태 전이, 권한/출제 revision, 비동기 취소, 브라우저 제한 시간, 정답 정규화, BGM 원상복구, HMAC 실제 HTTP 요청, 공개 전 정답 비노출을 포함합니다.

로컬에 승인된 Paper 테스트 파일·EULA·정제 월드가 있을 때 격리된 fixture를 실행할 수 있습니다.

```powershell
mvn -B -ntp -f noqui/plugin/pom.xml dependency:build-classpath -Dmdep.outputFile=target/smoke-classpath.txt
python noqui/plugin/smoke/run_paper_smoke.py
```

fixture는 `.runtime/noqui-plugin-smoke-*` 아래에서만 실행하며, 원본 월드와 라이브 서버를 수정하지 않습니다. 실제 Paper를 두 번 부팅하여 월드/스폰/경계, 네이티브 Dialog 생성, 서비스 등록, 빈 서버 시작, Moma 런타임 재로드와 종료 및 활성 상태의 재시작 복원을 확인합니다. 실제 클라이언트 화면과 브라우저 오디오 청취 검증은 별도로 수행해야 합니다.
