# Noqui 1.0.1

Paper 26.3 / Java 25용 노래퀴즈 플러그인입니다. 오디오는 Rust 서비스가 처음 115초(짧은 곡은 전체)를 약 48kbps Ogg Opus로 캐시하고 브라우저가 재생합니다. 게임·출제권·정답·점수는 Paper가 결정합니다.

## 빌드

저장소 루트에서 순서대로 실행합니다.

```powershell
python noqui/lobby-assets/build_pack.py --check
python noqui/lobby-assets/test_pack.py
mvn -B -ntp -f noqui/plugin/pom.xml clean install
mvn -B -ntp verify
cargo test --locked --manifest-path noqui/web/Cargo.toml
```

산출물은 `noqui/plugin/target/noqui-plugin-1.0.1.jar`, `target/mc-luck-defense-1.0.26.jar`입니다. Moma는 Noqui API에 provided 의존성을 사용하며 API는 Noqui JAR에만 포함됩니다. Noqui 없이 Moma만 기동하는 경로도 유지합니다. 두 플러그인을 함께 교체한 뒤 정상 재시작합니다. Moma 런타임 재로드는 매번 현재 서비스 제공자를 조회합니다.

팩의 소스와 생성·검증 방법은 [로비 에셋 안내](lobby-assets/README.md)를 따릅니다. 검증한 `noqui/lobby-assets/lobby-pack.properties` 하나만 JAR 루트에 포함하며 ZIP은 포함하지 않습니다. 팩 ZIP을 해당 내용 해시의 공개 URL에 먼저 게시한 후 플러그인을 기동합니다. 기존 `plugins/Noqui/lobby-pack.properties`가 있으면 자동 덮어쓰지 않으므로 팩을 바꿀 때 검증한 새 descriptor를 함께 반영합니다. CI는 Python 표준 라이브러리로 팩 재현성과 descriptor를 먼저 확인한 뒤 Maven을 실행합니다.

## 설정과 이용

정제된 `noqui_cabin` 월드를 서버 정지 중 반입합니다. 기본 스폰은 `(411.5, 11, -205.5)`, 경계 중심은 `(416, -192)`, 크기는 250입니다. 바깥 청크는 void generator를 사용하며 스폰 안전성과 월드 보호를 적용합니다.

`plugins/Noqui/config.yml`의 bridge 주소는 루프백 `http://127.0.0.1:8788`, 공개 주소는 `https://noqui.danta.qzz.io`입니다. `bridge.secret-file`에는 Rust와 같은 32바이트 키 파일 또는 64자리 16진수 키 파일을 지정합니다. 실제 키·`songs.yml`·`credits.json`은 비공개 서버 데이터입니다. 웹 설정은 `deploy/`를 따르며 Minecraft 주소는 `mud.danta.qzz.io`입니다.

OP 명령은 `/noqui start [rounds]`, `limit <rounds>`, `stop`, `skip force`, `hint`, `pause`, `resume`, `give <player> [amount]`, `status`입니다. 일반 참가자는 `/noqui`로 메뉴를 열고 `/noqui skip`으로 투표하며 `/noqui leave`로 퀴즈에서 나갑니다. `/noqui start`는 무제한, `/noqui start 200`은 최대 200라운드입니다. `/noqui limit 0`으로 무제한 전환하며 양의 정수로 실행 중 제한을 바꿉니다. 이미 시작한 라운드보다 낮은 양수 제한은 거절하고, 남은 제한을 초과한 대기 곡은 취소·반환합니다. 콘솔은 접속자가 없어도 시작할 수 있습니다.

퀴즈 시작 시 활성 디펜스·관전 세션이 없는 모든 접속자를 현재 월드와 관계없이 cabin으로 안내합니다. 진행 중인 디펜스 참가자·관전자는 현재 위치에서 동시에 참여하며, 5번 칸 노래퀴즈 아이콘으로 메뉴를 엽니다. 이후 퀴즈에서 나갔다면 같은 아이콘으로 다시 참여합니다. cabin 나침반은 새 디펜스를 바로 시작합니다. 퀴즈 회원권·브라우저 연결·출제권·BGM 복구 기록은 유지되며 디펜스 종료 시 활성 퀴즈 cabin으로 돌아옵니다. 디펜스 중 퀴즈 종료·이탈은 전장·관전·디펜스 도구·게임 모드를 변경하지 않습니다. F키는 cabin에서 퀴즈, 디펜스에서 기존 디펜스 메뉴를 엽니다.

입장하면 브라우저 연결 창을 먼저 엽니다. 발급된 60초 링크의 `연결` 버튼과 `닫기`만 표시하며, 메뉴에서 연결 창을 다시 열면 새 링크를 발급합니다. 기존 요청의 늦은 응답은 새 회원권이나 세션에 표시하지 않습니다.

출제권은 UUID별 영구 잔액입니다. OP의 `give`는 기본 1개, 한 번에 1..1000개를 지급합니다. 접속 이력이 있는 오프라인 플레이어도 지급할 수 있고 최대 보유량은 1,000,000개입니다. 자동 순번·정답자 지급은 없습니다. 메뉴에서 보유 출제권을 확인하고 유효한 곡을 제출하면 1개를 예약합니다. 한 사람당 재생 전 제출은 한 곡, 현재 곡을 포함한 작업 수는 최대 64곡이며 남은 제한 라운드를 넘겨 받지 않습니다. 제출을 받는 즉시 대기 곡도 비동기 변환을 시작하고, 차례가 오면 준비된 결과를 재사용합니다. 준비 실패·재생 전 취소/이탈·종료 시 한 번만 반환하고 재생 시작 때 사용을 확정합니다. 재시작 시 미확정 예약은 반환하며 대기열은 복원하지 않습니다. 잔액 파일이 손상되면 자동 초기화하지 않고 플러그인 기동을 중단합니다.

라운드는 기본 무제한이며 명령으로 0(무제한) 또는 최대 2,147,483,647까지 제한할 수 있습니다. 준비 실패는 라운드를 소비하지 않습니다. 대기열을 자동 진행하며 비면 제출을 기다립니다. 마지막 라운드가 끝나면 5초 공개 후 결과를 표시하고 종료 상태와 `quiz-active: false`를 저장합니다. `round-seconds`는 1..115이며 실제 오디오 길이를 넘지 않습니다. 브라우저 준비는 최대 20초 대기하고, 전달 여유 1초와 3·2·1 카운트다운을 예약합니다. 해당 예약의 웹 수락 후 재생과 정답 접수를 시작합니다.

제목·태그는 대소문자/공백/기호를 무시한 부분 문자열로 판정합니다. 출제자는 자기 곡에서 득점할 수 없습니다. 최초 정답자만 득점하며 경쟁 점수는 정답당 1점입니다. 별도의 영구 정답 포인트는 기본 1이며, `title-bonus: true`이면 제목을 맞힌 경우 2를 받습니다. 같은 라운드·UUID 보상은 한 번만 지급됩니다. 점수·정답 포인트·출제권·별빛은 각각 분리됩니다. 기본적으로 첫 정답 후에도 곡을 계속 재생하고 `match-skip: true`이면 즉시 5초 공개로 넘어갑니다. 참가자 스킵은 현재 참가자의 엄격한 과반수, UUID당 라운드별 한 표이며 이탈 시 다시 계산합니다. OP만 강제로 넘길 수 있습니다.

일시정지는 재생 위치·남은 시간·힌트 시간을 고정하고 정답을 받지 않습니다. 재개는 같은 위치에서 새 카운트다운으로 시작합니다. 최초 힌트는 원문 한글 초성과 영문/숫자의 밑줄이며, 이후 무작위로 약 25%씩 공개하되 최소 한 글자를 남깁니다. `auto-hint: false`가 기본이고 true이면 재생 중 9초마다 진행합니다.

cabin HUD는 점수판·TAB 점수·보스바·카운트다운·정답·TOP 10을 표시합니다. 디펜스에서는 Noqui 보스바와 채팅·작은 효과음만 사용합니다. BGM은 참가 시 원본 키의 존재 여부와 원시 BYTE를 별도로 저장한 뒤 OFF로 시작합니다. ON이면 디펜스 참가자·관전자는 기존 세션 재생 목록을, cabin 참가자는 Moma 기본곡을 사용합니다. cabin 인벤토리 복구 기록은 별도이며 디펜스 중 퀴즈 이탈 때 인벤토리를 복원하지 않습니다. 비정상 종료의 기존 복구 마커도 다음 접속에서 처리합니다.

`quiz-active`가 true였던 정상 재시작은 `quiz-limit`에 저장된 제한으로 새 제출 대기 상태를 만듭니다. 이전 곡·타이머·작업·브라우저 회원권은 재사용하지 않습니다. 점수는 한 실행에 한정되며 출제권 잔액과 개인 제출 기록은 보존합니다.

## 별빛과 상점

`/money`는 내 별빛 ✦와 정답 포인트를 보여 줍니다. Moma는 실제 디펜스 참가자에게 세션에서 도달한 최고 라운드 × `plugins/MCLuckDefense/rewards.yml`의 `starlight-per-round`(기본 1)를 지급합니다. 관전자는 보상을 받지 않습니다. 자연 종료·퇴장·접속 종료는 같은 세션 UUID와 플레이어 UUID로 한 번만 지급하며, 저장된 보상 대기열을 재시도합니다. 실행 중 리로드는 보상을 지급하지 않습니다.

cabin의 별빛 상점 NPC와 퀴즈 메뉴의 상점 버튼에서 구매합니다. 출제권은 별빛으로만 사고, 가젯은 별빛 또는 정답 포인트 중 선택합니다. 꾸미기는 기본 별빛이며 두 게임에서 표시됩니다. 가젯과 이단 점프는 cabin에서만 적용합니다. 구매 내역과 출제권 지급은 각 저장소의 동일 거래 ID로 재시도해 재시작 후 중복 지급을 막습니다. 리소스팩 URL·해시·가격과 로비 기능은 `lobby` 설정 및 별도 팩 자료를 따릅니다.

## 검증

Maven 검사는 크레딧 예약/확정/반환/재시작, 유한 라운드, 투표, 일시정지와 힌트, 비동기 취소, HUD 복구, 동시 참여, BGM 복구, HMAC 실제 HTTP 요청, 공개 전 정답 비노출을 포함합니다.

승인된 Paper 파일·EULA·정제 월드가 있을 때 격리된 fixture를 실행합니다.

```powershell
mvn -B -ntp -f noqui/plugin/pom.xml dependency:build-classpath -Dmdep.outputFile=target/smoke-classpath.txt
python noqui/plugin/smoke/run_paper_smoke.py
```

fixture는 `.runtime/noqui-plugin-smoke-*` 안에서 Paper를 두 번 부팅해 월드·스폰·경계, 네이티브 연결 창, 서비스 등록, 빈 서버 시작/종료, Moma 런타임 교체와 활성 상태 재시작을 확인합니다. 실제 클라이언트 화면과 브라우저 청취는 별도 검증 대상입니다.
